# Планувальник раціону

Облік продуктів → нечітка оцінка терміновості → жадібний план на тиждень → список докупівлі.

## Запуск

```bash
python -m venv venv
venv\Scripts\activate          # Windows;  macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Відкрити http://127.0.0.1:8000 (документація API: /docs).
За замовчуванням використовується SQLite (файл `fridge.db`). Для PostgreSQL задати змінну:

```
DATABASE_URL=postgresql+psycopg2://user:password@localhost:5432/meal_planner
```

Тести: `pytest`

## Структура

| Папка/файл | Призначення |
|---|---|
| `app/core/config.py` | конфігурація, зокрема `DATABASE_URL` |
| `app/core/templates.py` | спільний екземпляр `Jinja2Templates` |
| `app/db/` | SQLAlchemy Base, підключення до БД і моделі |
| `app/domain/fuzzy.py` | нечітка оцінка терміновості (тип Сугено, 7 правил) |
| `app/domain/planner.py` | жадібний планувальник (baseline) |
| `app/domain/recipes.py` | локальна база рецептів |
| `app/services/products.py` | підготовка продуктів для відображення |
| `app/api/routes/` | FastAPI-маршрути для сторінки, продуктів і планування |
| `app/main.py` | створення застосунку та підключення маршрутизаторів |
| `tests/test_core.py` | тести нечіткої логіки й планувальника |

## Що показати керівнику

1. Кнопка «Демо-набір»: таблиця сортується за терміновістю, зі шкалою 0–1.
2. Продукт зі статусом «відкрито» отримує вищу терміновість, ніж запечатаний із тим самим терміном.
3. «Скласти план»: 7 днів із сніданками, обідами, вечерями, batch cooking-залишками та списком докупівлі.

## Відомі обмеження (це і є простір для дослідження)

- Планувальник жадібний: не враховує, у який саме день спливає термін (курка з терміном 1 день може потрапити на другий день). Саме це має виправити багатокритеріальна оптимізація.
- Один критерій. Бюджет і різноманітність додаються на наступному етапі.
- Одиниці в запасах і рецептах мають збігатися.
- Ціни поки не враховуються.
