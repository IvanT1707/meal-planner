# Технічна специфікація та дорожня карта (Living Spec)

**Тема БКР:** Інтелектуальна система планування раціону харчування з мінімізацією харчових відходів  
**Англійською:** Intelligent Meal Planning System Using Multi-Criteria Optimization and Fuzzy Logic-Based Freshness Assessment

---

## 1. Бізнес-логіка та наукова база

### 1.1. Оцінка свіжості (Нечітка логіка)
* **Джерело:** USDA FoodKeeper (безпечні терміни зберігання до/після відкриття та за зонами зберігання).
* **Категорії (7):** `meat_fish`, `dairy`, `produce_soft`, `produce_hard`, `bakery`, `prepared`, `pantry`.
* **Зони зберігання (3):** `fridge` (холодильник), `freezer` (морозилка), `pantry` (комора / кімнатна температура). Автопідстановка рекомендованої зони при виборі категорії.
* **Правило безпеки:** вичерпання безпечного терміну після відкриття (`>= 90%`) або зберігання швидкопсувних продуктів поза холодильником дає критичну терміновість (`1.0`).
* **Пояснюваність (Explainability):** кожна оцінка терміновості супроводжується коротким текстовим обґрунтуванням для користувача (причина пріоритету).

#### 1.1.2. Облік запасів (Каталог + Партії FEFO):

* **Каталог інгредієнтів (Ingredient):** вибір продукту зі стандартизованого довідника (з пошуком), щоб унеможливити друкарські помилки та гарантувати точний збіг із рецептами через ingredient_id.

* **Партійний облік (InventoryBatch) та FEFO:** повторна покупка того самого продукту з іншою датою придатності створює нову партію, але в UI групується під одним продуктом. Списання при готуванні відбувається за принципом FEFO (First Expired, First Out).

* **Виконання плану:** згенерований план зберігається в БД (PlannedMeal) із прив'язкою до реальних дат (підсвічування «Сьогодні»). Підтвердження приготування («Приготовано») автоматично списує інгредієнти з найближчих партій.

### 1.2. Модель раціону та рецептів
* **Структура тижня:** 7 днів × 3 прийоми їжі (сніданок, обід, вечеря).
* **Кілька порцій (Batch cooking):** рецепти мають `servings` (к-сть порцій) та `keeps_days` (днів зберігання готової страви). Приготування 1 раз (напр., борщ на 4 порції) закриває кілька слотів без повторного списання інгредієнтів.
* **Профіль користувача:** розрахунок добової потреби в калоріях за формулою **Mifflin–St Jeor (1990)** + харчові обмеження (вегетаріанство, без лактози тощо) + масштабування порцій.

### 1.3. Наукове ядро (Для Розділів 2 та 4 БКР)
* **Baseline:** жадібний алгоритм (уже є).
* **Оптимізація:** багатокритеріальна оптимізація (`pymoo` / `OR-Tools`) — мінімізація відходів, бюджет, різноманітність (+ узгодження уподобань у груповому режимі) з вибором із Парето-фронту.
* **Пояснюваність (XAI):** пояснення вибору кожної страви + динамічний перерахунок тижня при відхиленні.
* **Адаптація:** підлаштування ваг критеріїв на основі історії вибору користувача (`scikit-learn`).
* **Експеримент:** порівняння жадібного, однокритеріального та багатокритеріального підходів за метриками (частка використаних термінових продуктів, вартість, різноманітність).
